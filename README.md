# 贴吧 CK 导入比特浏览器工具 v0.3.0

Electron + Vue 3 独立桌面工具。只管理本机贴吧 CK、比特浏览器窗口绑定及登录检查，不包含发帖、采集、目标贴吧分配或订阅。

从 `/Users/buge/百度贴吧发贴` 的账号模块提取行为：复用了 `tieba-accounts.js` 中的只读页面登录识别及 CK 检测逻辑，参考其写入顺序与窗口互斥；重新实现独立加密账号库和桌面界面，不依赖原服务器，也不修改原项目文件。

## 开发、运行与打包

开发电脑需要 Node.js 22.12+。最终安装包使用者不需要 Node.js，也不需要单独安装 Playwright 浏览器；窗口检查连接比特浏览器自身的 Chromium。

```sh
npm ci
npm test
npm run desktop
```

```sh
npm run test:desktop
npm run dist:win
npm run dist:mac
```

`test:desktop` 启动真实 Electron，用临时账号库及虚构凭据验证界面，不连接实际比特窗口。需要桌面会话和可用的系统密钥库。测试结束删除临时账号库。

安装包输出至 `release/`。Windows x64 / macOS ARM64、x64；默认未配置签名、公证。也可以手动运行 GitHub Actions 的 Build desktop installers 工作流下载安装包，工作流不自动发布。

## 使用流程

1. 添加或批量导入 CK。账号先加密保存在本机，不创建窗口，也不修改已有浏览器。
2. 在顶部填写比特 Local API 地址和可选 Token，点击连接。默认 `http://127.0.0.1:54345`，以比特设置为准。Token 只保留在内存。
3. 账号行点击“创建 / 绑定”，创建独立窗口或选择已有窗口。一个窗口只能绑定一个本地账号。子账号创建时必须填所属分组 ID。
4. 点击“导入到窗口”，确认替换该窗口的百度登录状态。工具先读取实时 Cookie（运行中窗口）、关闭并确认窗口退出，再更新保存的 CK，保留非百度域名 Cookie。
5. 重新打开窗口、停止旧百度页面、核对载入的登录 Cookie，再替换百度运行时 Cookie，读取新的贴吧页面判断登录。验证码页面保留，人工处理后可通过“更多 → 检查窗口登录”重新检查。
6. 更新 CK 只更新本地库；需要再次点击“导入到窗口”应用新 CK。创建成功、写入失败时保留绑定，重试复用同一窗口。

顶部显示未连接时，远程窗口操作禁用；本地保存、编辑、移除和 CK 检测仍可使用。重启工具后需要重新连接比特。

## 支持的导入格式

普通 CK：

```text
BDUSS=xxx; STOKEN=xxx;
账号名称----其他字段----BDUSS=xxx; STOKEN=xxx;
账号名称----BDUSS=xxx;
```

未填写备注的账号按现有账号编号继续自动命名，例如 贴吧账号001、贴吧账号002；多次导入和重启后不会从001重新开始。自定义备注原样保留。

中间导出字段不会保存。Cookie 值中的 `=`、百分号编码和 CK 部分的 `----` 保留。

单个 Cookie JSON：

```json
[{"name":"BDUSS","value":"xxx","domain":".baidu.com","path":"/"}]
```

也支持 `{"cookies":[...]}`。

批量 TXT 每行一个账号；空行不导入，错误行号包含原空行。批量 JSON 支持：

```json
{"accounts":[{"note":"账号备注","cookie":"BDUSS=xxx; STOKEN=xxx;"}]}
```

也支持直接账号数组，以及 `cookie` 为 Cookie 数组的账号记录。JSON 报告中的序号表示数组项序号。

限制：每次最多 500 个账号、输入或文件最大 1MiB，单个 CK 最大 80KB、最多 300 项 Cookie。逐条保存，单条失败不影响其他项；报告列出成功、重复、失败数量与具体行号。重复以 BDUSS / BDUSS_BFESS 的登录凭据哈希识别；不同凭据是否属于同一 UID，保存时无法离线判断。

空名称、空值、`undefined`、`null`、导出元数据会清理。只接收百度域名 Cookie；同名登录凭据有不同值时拒绝，防止混合多个身份。普通非登录 Cookie 按域名、路径、名称去重，保留最后一项。支持只有 BDUSS_BFESS 的 CK。

原始 Cookie 请求头不包含域名、路径、过期时间：默认 `.baidu.com`、`/`、会话 Cookie、Secure；常见登录项推定 HttpOnly。JSON 中有效属性会保留，已过期或非法的过期时间会报错。

## 三类状态

- **CK 已保存**：仅表示格式通过且本地加密写入成功。
- **CK 检测有效**：通过参考项目的只读 `/mo/q/sync` 请求确认登录身份；单独记录检查时间，不修改窗口状态。
- **窗口已登录**：打开真实贴吧页面，读取 Vue/Pinia、PageData 或明确的登录菜单标记。没有昵称但有明确标记时仍显示已登录，可用备注识别。

窗口检查区分已登录、未登录或失效、人工验证和检查失败。最多读取页面 5 次，每次间隔 500ms，不发送帖子。遇到 `ERR_TOO_MANY_REDIRECTS` 时按参考项目恢复逻辑关闭并确认同一窗口退出，再重新打开一次、用新页面检查；恢复过程不重新写入 CK、不创建窗口。第二次仍出现重定向时明确报错并停止，不无限循环。CK 检测身份与页面 UID 不一致时标为检查失败。登录成功不表示有发帖权限。

“更多”提供修改备注、更新 CK、检查窗口登录、更换绑定、解除绑定、关闭窗口和移除本地记录。批量选择可逐条检测 CK；失败项可以单独重试。导入格式错误的项目可重新填写后单独保存。

## 批量任务（v0.3.0）

账号列表支持 25 / 50 / 100 条分页。表头选择当前页；“全选筛选结果”选择当前搜索和状态筛选下的所有账号（最多 500 个）；“选择未绑定”便于只处理待创建窗口的账号。

选中账号后，通过“选择批量操作”执行：

- **创建并导入 CK**：已绑定的账号复用窗口，未绑定的账号先新建、保存绑定，再写入。写入失败后的重试不会重复新建。
- **仅创建窗口**：已绑定账号跳过，不写入 CK。可统一指定新建窗口的分组 ID。
- **绑定已有窗口**：逐个明确账号与窗口对应关系，或按空闲窗口顺序预分配后人工核对；不写入 CK。目标不能重复，也不能已绑定其他账号。
- **导入 / 重新导入 CK**：仅处理已绑定窗口的账号；确认汇总目标列表后，逐条替换百度 Cookie 并检查登录。
- **检测 CK / 检查窗口登录**：逐条显示有效、失效、验证或失败结果。
- **打开 / 关闭窗口**：未绑定的账号跳过。
- **解除绑定 / 移除本地记录**：核对名单并确认后执行，保留比特窗口；移除不自动关闭窗口。

批量队列在 Electron 主进程串行执行，单项失败继续后续项。任务面板实时显示进度、当前账号、逐项结果、成功／失败／跳过／未执行数量。可以停止后续任务，当前请求会完成；创建后、写入前停止时会保留已创建的绑定。支持重试全部失败项或单条失败项；写入和移除等操作重试时仍需重新核对确认。

执行期间不能同时更改连接、修改账号或启动另一批任务。完成前关闭应用会提示等待。队列和报告仅保留于本次运行，账号与绑定仍正常持久化；崩溃后不会自动重放任务。批量打开会逐个打开所选窗口，请根据机器资源选择数量。

## 本地数据与错误恢复

`userData/account-vault/accounts.json` 保存元数据及 AES-256-GCM 密文；每次加密使用随机 96 位 IV，认证标签独立保存。32 字节随机密钥通过 Electron `safeStorage` 由系统密钥库保护后存入 `vault.key`。不提供明文降级；密钥缺失、损坏或系统安全存储不可用时拒绝打开账号库，避免覆盖旧数据。

普通账号列表不返回 CK、密文和凭据哈希；错误信息隐藏提交的 Cookie 值与 Token，不输出原始响应。关闭导入弹窗清空尚未保存的 CK，成功导入后清空输入。移除记录只删除本地账号和加密 CK，不删除比特窗口。磁盘或系统备份中的历史副本不由此操作删除。

账号库使用临时文件替换；保存失败回滚内存记录。同一账号及其窗口的导入、检查、更换绑定等操作互斥。工具只能约束自身操作，使用期间请勿从其他程序或比特界面同时修改同一窗口。

创建前先保存“结果待核对”标记。HTTP 异常、超时、断连、无窗口 ID 时不会自动重复创建；请在比特浏览器核对，然后刷新窗口列表并手动绑定已创建的窗口。若确认没有创建，可在新建弹窗勾选核对确认后重新创建。明确业务拒绝后允许重试。新窗口绑定在写入前保存，写入失败不会丢失绑定。

v0.1.0 只有迁移历史、没有保存 CK。本版使用独立 `account-vault/`，不会把旧历史当作已保存账号；请重新导入 CK，然后按需绑定原有窗口。原“百度贴吧发贴”的账号库也不会自动读取或更改。

可设置 `TIEBA_DATA_DIR` 为独立的绝对目录来隔离测试或另一套比特账号。加密密钥受操作系统用户保护，不能仅复制 `accounts.json` 到另一台机器使用。

## 验证与实际限制

已通过 38 项单元／模拟集成测试、Vite 生产构建、Electron 脚本语法检查，以及真实 macOS Electron 桌面冒烟测试。桌面测试覆盖单个加密保存、批量成功/重复/失败、列表不泄露 CK、关闭弹窗清空、搜索、本机模拟 HTTP API 连接、绑定不写入 CK、替换确认、批量关闭、批量解绑／绑定、62 个虚构账号的分页及最小窗口尺寸；已查看界面截图。

窗口接口顺序、运行时 Cookie 保留、并发锁和失败恢复由模拟测试验证。尚未使用真实有效账号与实际比特客户端完成创建、写入和登录联调；Windows 安装、macOS 安装包运行也尚未验证。不同版本比特的关闭状态、Cookie 同步和贴吧页面结构仍可能影响结果，异常时保留绑定并显示失败原因。
